**Key Architectural Decisions:**

1. **Single Page Application (SPA)** - React 18+ with React Router
2. **RESTful API** - WordPress REST API (/wp-json/hms/v1/*)
3. **Feature Gating** - License-based unlocking (not separate codebases)
4. **Database-First** - All tables created Day 1, used progressively
5. **Monorepo** - Single codebase for all tiers

7. STATE MANAGEMENT STRATEGY
═══════════════════════════════════════════════════════════════════════════════

**Approach: React hooks + Context (No Redux)**

Why no Redux:
- Application is not highly complex
- Most data is server-driven (REST API)
- React hooks + Context sufficient for our needs
- Simpler developer experience

**State Organization:**

1. **Global State (React Context)**
   ```javascript
   // src/contexts/AppContext.js
   const AppContext = createContext();
   
   - currentUser (WordPress user)
   - license (tier, features, limits)
   - permissions (capabilities)
   - settings (hospital info, configurations)
   ```

2. **Local Component State (useState)**
   - Form data
   - UI state (modals, tabs, collapse)
   - Filters (search, date ranges)
   
3. **Server State (Custom hooks with useEffect + useState)**
   ```javascript
   // src/hooks/usePatients.js
   function usePatients(filters) {
       const [patients, setPatients] = useState([]);
       const [loading, setLoading] = useState(false);
       const [error, setError] = useState(null);
       
       useEffect(() => {
           fetchPatients(filters);
       }, [filters]);
       
       return { patients, loading, error, refetch };
   }
   ```

**Caching Strategy:**
- Use React Query or SWR (optional) for advanced caching
- Or manual caching with useRef for expensive queries
